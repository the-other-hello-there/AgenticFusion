## MCP output, timeout, and crash

- **`The operation timed out.`** The script can still be running in Fusion, with later calls queued behind it. Use the shared [bounded-run monitor](../../fusion-model/references/verification.md#bound-a-long-run), then inspect actual state when Fusion responds; do not blindly rerun the build. Split future heavy builds into batches and log progress to a scratchpad file.
- **Empty MCP output mid-session:** scripts may return an empty message even while `sys.stdout` works. Write results to a scratchpad file and read it with Bash for the rest of that session.
- **Save collision or `ECONNRESET`:** a scripted `doc.save()` started in the same second as an autosave and crashed Fusion with heap corruption `0xc0000374` after `NEUTRON_BUG_ALERT` floods in `BinaryBulkSaveVisitor`. The version was not saved; its crash-recovery backup was `not a valid zip package`. Follow the autosave timing and version checks in the [modeling MCP workflow](../../fusion-model/references/mcp.md) before another save.
- **Startup recovery dialog after a crash:** it blocks every MCP call, including read-only calls, with `The operation timed out.` Use a verified background control only when it preserves recovery files (Close retains recovery; never choose Delete). If compliant access is unavailable, record the blocker and ask the user to dismiss it; never move their cursor or force-quit.
- **Export timeout during save upload:** an export can return `The operation timed out.` and still finish; check output-file timestamps before retrying.

- **Exception after partial edits:** earlier deletions can remain. Independently inspect timeline, bodies, volumes and parameters before retry/recovery; a raised script does not establish unchanged CAD.
- **No progress or a second startup crash:** inspect process CPU-time progress and current logs without another long queued script. Allow startup to settle when initialization is active rather than repeatedly opening documents. Confirm unsaved/recovery state and use the lifecycle checkpoint/restart approval. Never treat a busy loop as cancelled or force-kill to meet a deadline.
