# Settings translation and verification

Read when building/changing a print setup. `FDM-Slicing.md` is the policy authority. The mapping below is a starting point for Orca-family builds, not a portable preset or version allowlist. Inspect selected-build help/schema and resolved native values/types; an absent control is a capability limit. Native JSON commonly uses string/list values even for numeric settings: preserve the installed format. Apply job-local overrides and read them back after profile loading/normalization.

## Translate the user rules

| Policy | Candidate native controls | Evidence needed |
| --- | --- | --- |
| R1/R2: surfaces versus adjacent layers | `top_surface_pattern`, `bottom_surface_pattern`, `internal_solid_infill_pattern` | Concentric exposed skins and linear adjacent internal-solid paths on every relevant local shell. Do not set sparse infill to 100% to create solid shell layers. |
| R3/R4: density and directly stacked infill | `sparse_infill_density`, `sparse_infill_pattern`, pattern direction/rotation | Job purpose, final designation when high, actual percentage, and repeated XY path placement across adjacent layers. Ordinary rectilinear alternates; use a verified aligned variant or grid when direct stacking is required. |
| R5: minimum walls and connection | `wall_loops`, `alternate_extra_wall`; Bambu-family `embedding_wall_into_infill` when exposed | At least 2 nominal loops outside intentional-flexibility exceptions, alternating extra paths, and actual wall/infill connections. Disable optional single-wall-on-top/first-layer shortcuts unless intent justifies them. The two connection features are distinct; missing one must be reported. |
| R6/R10: thin features | `wall_generator`, `detect_thin_wall`; Arachne minimum-feature/minimum-width controls | Compare geometry to both actual nozzle diameter and configured line width. Use the rule's different thresholds correctly. Check a narrow functional feature survives and its dimensions remain acceptable. |
| R7: combined infill | `infill_combination`, `infill_combination_max_layer_height` | Direct stacking qualifies before enabling; effective combined heights and volumetric demand remain within calibrated limits. |
| R8/R9: supports | `independent_support_layer_height`, `support_type`, `support_style` | Effective independence, intended small-feature/tree or large-overhang/normal contact, gaps and removability. Style enum names differ across builds. |
| R11/R12: layers/shells | `top_shell_layers`, `bottom_shell_layers`, thickness controls and saved per-object adaptive profiles | At least 3 actual solid layers on each side, required thickness in mm, and the smoothed height schedule used by the slice. See [layer height](layer-height.md). |
| R13: object order | `print_sequence` and per-object order/clearance settings | Actual short/small-first sequence, collision-free toolhead/gantry/bed sweep, compatible supports/towers. No universal clearance radius is supplied. |
| R14: second interface material | Interface filament/extruder mapping, `enable_prime_tower`, purge and interface settings | Specific approval, actual material assignment, effective tower, clean transitions and support/toolpath checks per [support materials](support-materials.md). |

Orca documents separate [shell surfaces/count/thickness](https://github.com/OrcaSlicer/OrcaSlicer/wiki/strength_settings_top_bottom_shells), [infill and internal solid patterns](https://github.com/OrcaSlicer/OrcaSlicer/wiki/strength_settings_infill), and [wall generators](https://github.com/OrcaSlicer/OrcaSlicer/wiki/quality_settings_wall_generator). Bambu's [native setting definition](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) identifies `embedding_wall_into_infill`; do not treat it as a renamed `alternate_extra_wall` or invent support for it in another build.

## Compatibility checks that change decisions

- Classic thin-wall detection and Arachne are alternative mechanisms. Orca disables the thin-wall checkbox with Arachne. With Alternate extra wall, apply the user's reduced vertical-shell preference: Orca Moderate rather than All; Bambu `partial` rather than `enabled` where those enums exist. Inspect the actual schema and read back after normalization; do not disable R11's three-layer/thickness minimum to resolve the conflict. Orca's [native conflict handling](https://raw.githubusercontent.com/OrcaSlicer/OrcaSlicer/main/src/slic3r/GUI/ConfigManipulation.cpp) switches this combination to Moderate; Bambu's [native enums](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp) define its different values. See also [Orca wall settings](https://github.com/OrcaSlicer/OrcaSlicer/wiki/strength_settings_walls).
- Detect narrow internal solid infill may substitute concentric paths despite a linear internal-solid selection. Inspect those local layers and disable that substitution where it violates R2. Combined infill's height cap applies to sparse infill, not the normal wall height; use the real combined height in checks. [Orca strength advanced](https://github.com/OrcaSlicer/OrcaSlicer/wiki/strength_settings_advanced).
- The documented Orca support implementation can ignore independent support height when a prime tower is present and omit it for Organic style. Enable the requested control, then verify effective behavior; do not claim a true independence that the engine cannot produce. Choose a compatible style/build if the user accepts it; retain the required prime tower for an approved multimaterial interface. [Orca support advanced](https://github.com/OrcaSlicer/OrcaSlicer/wiki/support_settings_advanced).
- Sequential multi-object mode and a prime tower also need a compatibility check: some Bambu-family normalization paths disable the tower in that mode. Verify the actual build rather than assuming R13 and R14 both took effect. Separate one-object plates/runs can avoid that conflict while retaining the required tower. [Bambu native normalization](https://raw.githubusercontent.com/bambulab/BambuStudio/master/src/libslic3r/PrintConfig.cpp).
- Do not encode an adaptive/smoothed profile as an invented single boolean or CLI flag. Reuse a verified saved layer profile, use a supported API, or explain a necessary non-disruptive UI setup step. See [layer height](layer-height.md).

## Additional practices from research

These are recommendations subordinate to verified design intent and the user rules. Numerical values from guides are starting guidance, not measurements of this printer.

1. **Use a verified material/profile baseline.** Scope temperature, flow ratio, pressure advance, retraction and volumetric-flow calibration to the actual spool/nozzle/hotend. Check spool condition and follow its manufacturer's drying/storage guidance. Preserve inherited parents and custom G-code. Use `fdm-calibrate` when evidence is missing or a defect needs a measured test; do not compensate a calibration problem by increasing infill. Orca's [calibration guide](https://github.com/OrcaSlicer/OrcaSlicer/wiki/calibration_guide) explains the dependencies; measured test files/results belong in project context.
2. **Check the load path before density.** Continuous perimeters, shell thickness and orientation deserve attention before a denser core. More sparse infill is not a quantified strength improvement. Keep seams and support contacts away from functional interfaces when feasible without changing approved CAD intent. [Prusa layers and perimeters](https://help.prusa3d.com/article/layers-and-perimeters_1748) supports the perimeter-versus-infill distinction; the load-path and interface checks are engineering synthesis for this workflow.
3. **Verify support under solid roofs and infill crossings.** Grid has same-layer intersections that can accumulate material; aligned rectilinear avoids those intersections but may leave a roof poorly supported when its first solid paths are parallel. Preserve directly stacked sparse infill and choose a compatible solid-roof direction/spacing, then preview for nozzle contact and unsupported spans. Gyroid's different directional behavior does not supersede R4 automatically. [Prusa infill patterns](https://help.prusa3d.com/article/infill-patterns_177130).
4. **Limit real extrusion demand.** Check peak volumetric flow, not average speed, especially where adaptive layers grow or infill is combined. Keep the actual nozzle/material calibration ceiling; do not copy another printer's flow rate. Verify small-layer cooling/slowdowns and temperature continuity, particularly during sequential printing. Follow the [layer-height checks](layer-height.md); cooling-sensitive results need measured validation.
5. **Treat sequential layout as a swept-volume problem.** Verify complete head/gantry clearance, build plate motion, already-printed parts, supports, brims and tower. Small-first does not by itself establish clearance. If tall-object clearance is unknown or fails, use separate plates/runs rather than an unsafe sequence. The [Prusa sequential-printing guide](https://help.prusa3d.com/article/sequential-printing_124589) explains why accurate clearance configuration matters; use the actual printer's geometry instead of importing Prusa defaults.

## Record and verify

For each relevant rule, keep a concise status: **applied**, **not applicable**, **design-intent exception** (with reason), or **unresolved capability**. This can be a job note/manifest, not a large repeated checklist in chat. Read back resolved values after any profile switch or slice-time normalization; verify the affected paths in final UI preview. Record output/source/profile hashes, warnings, actual estimates/units and pending checks in `Project.md`. A rendered preview or generic material label never establishes fit, adhesion, isotropic strength or an actual successful print.
