## Timeline
- **Plan the dependency chain from design intent, then organize the timeline around it.** Establish meaningful user parameters and stable layout or interface references before the features they drive; parameters are not timeline items. Use a shared layout or skeleton only where several features or components genuinely need a common driver. A datum or reference derived from a later solid belongs after that solid. Prefer editing the sketch or feature that owns a shape over adding a downstream patch.
- **Create named Timeline groups when they make a substantial part or assembly easier to navigate.** Group contiguous features by a coherent design decision, functional area, or local modeling stage. Possible names include `Interface layout`, `Main housing`, `Mounting bosses`, `Cable path`, and `Edge finishing`; use only those that fit the actual design, and repeat a stage later if the dependency chain calls for it. Groups are not Browser folders, component ownership, or a mandatory sequence of feature types. Inspect existing groups before inserting a feature; update boundaries if needed, but do not move a healthy feature merely to tidy a group. Fusion groups contain a contiguous range and cannot nest; `timeline.timelineGroups.add(startIndex, endIndex)` uses inclusive indices, and the returned group's `name` can be set. Re-read indices after timeline edits. Do not create empty groups or placeholder features.
- **Feature order (user rule): place each change after its inputs and before the features that truly depend on it.** Shape-defining solids and bosses often precede the holes, cuts, and rounds they support; cosmetic edge fillets and chamfers usually follow the geometry whose edges they finish. Functional blends, rounds used by later operations, shell requirements, or other design intent can put a fillet earlier. If the same functional shape can be expressed more robustly in a controlling sketch, datum, or parameter, prefer that; do not force a workaround that changes function or creates fragile references. Bridge steps, teardrops, and other print treatments follow their own dependencies. A cut added after rounds can leave partial rounds, steps, and unchamfered bed edges. After insertion or regrouping, verify group membership, downstream references, feature health, constraints, body count, volume, fit, and motion as applicable.
- **Marker (`timelineObject.rollTo(...)`; return with `timeline.moveToEnd()`):**
  - To insert before an existing feature, `rollTo(True)` on it, then create the new feature; it lands at the marker. Then re-check every later feature's health and re-select the edges of fillets and chamfers that changed.
  - Rolling invalidates occurrence handles fetched before it, so fetch them afterwards. At an early marker a sub-assembly occurrence may not exist yet, so take any occurrence of the component (`o.component.name == ...`).
  - Some feature inputs can be read only after `feature.timelineObject.rollTo(True)`, which a `readOnly` script can't do (`Didn't roll editing feature back`): fillet `edgeSet.edges`, pattern `inputEntities`, `ReplaceFaceFeature.targetFaces`, and a sketch's `referencePlane` when it is a face. Read `feature.faces` instead, or use a normal script. `ReplaceFaceFeature` has no source-face getter.
- **Reorder:** `TimelineObject.reorder(beforeIndex)` can't move an item to the very end (`beforeIndex` = count raises `InternalValidationError : featureAtIndex`); move the other items before it instead. Reorder is refused while the moved item fails to compute: delete the failing fillet (check that the feature list lost nothing else), then recreate it at its proper position.
  - A feature that targets a body can't move before the feature where that body's identity starts (a Combine, Split/RemoveBody, or the join that created it): `InternalValidationError : featureCanReoder` or `CIRCULAR_DEPENDENCY`. Use the earliest position after it. A sketch also can't move before the construction plane it lies on (same `featureCanReoder`); move the plane with it.
  - A reorder can change results without failing: a later edge-selected round loses an edge (`Edge 1 missing`, cached geometry), a teardrop loses its body (`No target body!`), or a hole fill moved before the old teardrops lets them re-open the caps inside the plug. Do each part's reorder in a script that compares body count, volume and the health list before and after, and raises (rolls back) on any difference; then try the next slot.
- **Deleting a feature silently deletes later features whose references were its faces or edges** (e.g. a chamfer on a deleted fillet's edges; corner rounds whose vertical edges ended on a deleted bed chamfer). A health check won't show it; re-list features after a delete.
- **Editing an earlier sketch that a later chain depends on:** `rollTo(True)` on the feature that consumes the sketch, edit the sketch there, reassign `feature.profile`, roll on to the next fragile feature to re-select its edges, then `moveToEnd()`. Editing at the end of the timeline recomputes every later feature after each change; an intermediate state broke a fillet and raised.
  - Reassigning an extrude's `profile` can silently replace its `participantBodies` with other intersected bodies. While rolled before the feature, set its intended participants explicitly as a Python list of `BRepBody`, then verify body count, feature health and exact final volume. A healthy cut with the wrong participants can still change the part.
  - Sketch distance dimensions are magnitudes. On the XZ plane sketch y is −Z, and an existing dimension may read `-( -( expr ) )`. Set a new one to the positive magnitude; a sign slip can silently flip the profile and cut the wrong region.
  - To remove a profile vertex: delete its dimensions and the edge to its neighbour, add a coincident constraint to the neighbour, reassign `feature.profile`, then re-select dependent fillets.
- **Don't widen an early cut to fix a later problem:** changing an early feature's extent can split the body, and every later `participantBodies` reference fails (`No target body!`). Restoring the value doesn't repair the references; use MCP undo for both transactions. Insert a new feature at the right position instead.

**Verify every build:** body count, bounding box (cm; ×10 for mm) and volume; every timeline item's `healthState` / `errorOrWarningMessage`; `sketch.isFullyConstrained`; then screenshots (see [Screenshot camera](helpers.md); call `viewport.fit()` when done); then a [flex test](helpers.md). Treat every active feature with `healthState != 0`, including warning state 1, as a failure to investigate; record unrelated baseline failures separately. A volume that doesn't return *exactly* after a flex means the geometry resolved differently (e.g. a flipped arc). A save can recompute stale cached geometry, so read back the saved version, modification state, volume, shell count and feature health before reporting success; repair and save again if any result changes.
