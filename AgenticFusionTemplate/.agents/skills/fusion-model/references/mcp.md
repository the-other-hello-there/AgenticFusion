## Fusion MCP workflow
- Scripts must define `def run(_context=None):`. The harness calls it after the top-level code runs. Return output with `print()`.
- Pass `readOnly: true` for inspection-only scripts. These are the only scripts that run while a Fusion command dialog is open; ask the user to close the dialog rather than closing it yourself.
- **The script namespace persists between calls and exec'd helpers share it.** Set every flag and input explicitly on each call: `globals().get('X', default)` can silently reuse an old `X`. Give helper globals unique names: a helper's `OUT` can replace a caller's output path. For long scripts, keep the file in the scratchpad and run `exec(compile(open(p).read(), p, 'exec'))` at top level.
- Don't name scratch modules after standard-library modules: a scratchpad `inspect.py` shadowed `inspect` for local Python, and `import numpy` failed. Run local analysis with `python -P` (doesn't prepend the script's folder), or use distinct names.
- Split heavy scripts into batches and log progress to a scratchpad file. After `The operation timed out.`, follow the `fusion-repair` skill; a script may still be running.
- An exception or timeout does not guarantee rollback: earlier deletions or edits may remain. Inspect actual timeline, bodies, parameters and volumes before recovery or retry. Use a verified checkpoint/trial copy; verify the scope and result of any MCP undo rather than assuming one script is one transaction. Only a local `Design.modifyParameters` batch has its documented all-or-none guarantee.
- **Scripted saves and autosave:** Fusion autosaves modified documents at observed 5- and 10-minute intervals. The newest AppLog at `%LOCALAPPDATA%\Autodesk\Autodesk Fusion 360\<id>\logs\AppLogFile*.log` gives the interval as `Autosave background thread started with saveTime: N` and logs `Started Autosave for: <doc>`; closing another document can trigger an off-grid `Started forced Autosave for: <doc>`. Before `doc.save()`, read the latest `Started Autosave` or `Started forced Autosave` time and save well clear of the next tick. If unsure, wait for a new start line and save just after it: ticks can be skipped when nothing changed since the last autosave (only read-only scripts ran), and the next can come a full interval later. Ticks are not reliably on the grid; a modified document went over 10 minutes without a tick at a 5-minute interval. Save in its own MCP call, then confirm `dataFile.versionNumber` against `app.data.findFileById(id).latestVersionNumber` (the document handle can still show the old number immediately after saving) before export. A save collision can crash Fusion; see the `fusion-repair` skill.
- **Check a parameter's sign before negating it in an expression:** a back face may already be stored negative, so `-param` lands on the wrong side. A sketch that flips sides this way can split the body.
- Look up the API with `queryType: "apiDocumentation"` (a `filter` like `adsk.fusion.LoftFeatureInput`, `apiCategory` member/class) instead of guessing.
- For an existing parametric design, try substantial changes in a full parametric copy with its real dependencies. A new scratch design can probe a new construction; copied solids or dimension-free probes cannot verify the original timeline or parameter response. Close only owned disposable drafts under the application-session save/ownership rules.
- Close unused reference/scratch documents promptly under the shared [application-session lifecycle](../../application-session/references/lifecycle.md). Before an agent-limit handoff or 12-hour app maintenance, finish/identify in-flight calls, save and verify through this workflow, and record a restart checkpoint. User restart approval never authorizes discarding an unsaved document or forcing a close.
- Only for an explicitly authorized full rebuild with a verified recoverable copy, to replace a saved design as a new version: `timeline.moveToBeginning(); timeline.deleteAllAfterMarker()`, delete the user parameters, rebuild in the same document, then `doc.save(msg)`.
- Name a new part with `doc.saveAs(name, app.data.activeProject.rootFolder, desc, '')`. The root component's name follows the document name.
- **Comparing with an earlier version:**
  - Open it with `app.documents.open(doc.dataFile.versions.item(i), True)`. This *replaces* the open document of the same lineage; the old handle then raises `An API Object refers to a deleted Object`.
  - It can instead return the already-open latest document unchanged, so check `dataFile.versionNumber` afterwards. If that happens, `doc.close(False)` first, then open the version from `app.data.findFileById(lineageId).versions` (the `versions` order isn't by number; match `versionNumber`).
  - Only do this when the current version is saved and unmodified.
  - To find a user's edits, dump user parameters, model-parameter expressions, per-component volumes and feature lists to JSON for both versions, then diff them.
  - Measure, then `close(False)`, then reopen the latest with the MCP document `open` and the lineage `fileId`.
- `AsBuiltJoint` has no `healthState`; use `joint.timelineObject.healthState`.
- `jointMotion.rotationValue` can't be set from a `readOnly` script (`Cannot modify the design from a read-only context`).
- An extrude from a sketch on an offset construction plane measures `OffsetStartDefinition` from the sketch plane, not the origin. Sketch on the origin plane and let the extent set the height ("No target body!" otherwise).
- Sketches placed on a HoleFeature's counterbore floor (bridge steps, teardrops) follow `counterboreDepth` edits.
- **Plugging an old hole with a join:** before creating it, check that a ring just outside the fill tool (excluding its teardrop cap) is all material by `pointContainment`. Otherwise use the exact old void shape (diameter plus teardrop) and confirm dV equals the void volume. Where a hole breaks out into a pocket or an edge round, fill only the span that will be re-cut.
- An extrude cut whose tool misses every participant body only warns (health 1, `No target body!`); it doesn't remove anything. A Combine cut whose tool body misses the target stays healthy. So for a trim that legitimately becomes empty over part of a parameter range, extrude the tool as a new body and Combine-cut it. Define its profile so it can't flip (e.g. a quadrilateral bounded by the moving plane and fixed offsets): a sketch triangle whose vertices cross over turns inside out and cuts elsewhere.
- **Split Body + Remove is fragile under parameter changes.** When the split misses its target or the bodies come out in a different order, Remove can delete the main body. Prefer bounded cut features.
- **Rebuilding a hand-made chain (Splits, RemoveBodies, Combines, face-offset planes, profile-based sketches) parametrically:**
  - Roll the marker to each step, `tm.copy` the body (union of all bodies), and difference consecutive states to get each step's net added and removed solids. Name each face by the feature that owns the coplanar face of the model, and convert its vertices into the part's design frame. Each delta is then a few planes that existing parameters already define.
  - Extra material a fill tool puts inside the existing body changes nothing, so its inner boundary may be any line that stays inside the body over the parameter range.
  - In one script: `tm.copy` the final body, delete the old items from the highest timeline index down, insert the new features at the old positions, then difference the result against the copy both ways. Reject the candidate unless both differences are 0 within the declared measurement tolerance, there is the expected shell count, and every feature is healthy. A forced exception is not a free or assured rollback; perform destructive trials only on verified disposable parametric copies and inspect actual state afterward. Bound long runs with progress logs.
  - Deleting the Combine where the body identity started broke nothing: later features re-bound to the remaining body.
  - Check edge-selected fillets and chamfers that touch the rebuilt area. Their edges appear and disappear as the parameter moves, and a sweep away from the value and back can leave one permanently `Edge N missing` (the volume does not restore; recover the verified trial/checkpoint). Move those edges out of the edge set and rebuild their geometry as sketch-based fills, e.g. a loft between parallel polygons for a 45° chamfer along a polyline.
  - Then sweep the parameter over its intended range and back in a bounded, logged trial, verifying every restore. Record each value's body count and health, and the parameter's own geometric limits.
- **Retargeting parameters:**
  - Find model parameters by their expression text, with spaces stripped, e.g. `p.expression.replace(' ', '')`, and rewrite them to reference new user parameters.
  - To tell apart sketch dimensions that share an expression, map each dimension's non-origin `SketchPoint` through `sketch.sketchToModelSpace`.
- `TemporaryBRepManager.copy(occurrenceProxyBody)` gives world-space geometry. Transform it and intersect it with `booleanOperation(..., IntersectionBooleanType)` to test paths without moving occurrences.
- `PointContainment` values: 0 = inside, 1 = on, 2 = outside.

## Long runs and parameter cleanup

Use the [bounded-run and evidence procedure](verification.md#bound-a-long-run) and shared `watch_fusion.py` before launching work that may exceed the MCP response timeout. Log a unique run ID, progress and an evaluated terminal result. After any non-success, inspect actual state; never infer rollback or start a duplicate build while the original may run.

Delete only nominated obsolete parameters, in dependency-aware passes. Verify each parameter is actually absent; `deleteMe()` return values differ across builds and the [API contract documents a success-reporting bug](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_UserParameter_deleteMe.htm). Stop on a pass with no deletion instead of spinning on the last item. The [shared helpers](../scripts/fusion_helpers.py) implement this bounded behavior and explicit-input batch parameter updates. Successful earlier deletions can persist if a later one blocks.

For export, select bodies explicitly when nested-occurrence STL export fails. Set tessellation and output units through the selected API; check export success, nonempty files and measured scale, and record units/provenance. A reference import creates a document and is not strict read-only execution. Close only the owned reference in `finally` and restore the previous active document.
